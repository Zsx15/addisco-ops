\# BRD — AI Révision Métier



\## Vision



Créer une plateforme IA de révision métier capable d’améliorer :

\- la mémorisation,

\- la compréhension,

\- la révision ciblée,

\- et la transmission des connaissances professionnelles.



Le système doit évoluer vers une plateforme pédagogique adaptative basée sur l’analyse des erreurs, la mémoire utilisateur et les neurosciences modernes de l’apprentissage.



\---



\## Contexte



Les procédures métier sont souvent :

\- longues,

\- complexes,

\- apprises passivement,

\- difficiles à mémoriser dans le temps.



Les systèmes actuels reposent majoritairement sur :

\- lecture passive,

\- quiz statiques,

\- faible personnalisation,

\- absence de mémoire pédagogique.



\---



\## Objectif principal



Créer un moteur IA capable de :

1\. comprendre des documents métier ;

2\. générer des questions pertinentes ;

3\. corriger les réponses ;

4\. identifier les lacunes ;

5\. suivre les erreurs ;

6\. adapter les futures révisions.



\---



\## Fonctionnement général



Le système fonctionne autour de plusieurs briques :



\- ingestion documentaire ;

\- découpage intelligent en chunks ;

\- embeddings sémantiques ;

\- RAG (Retrieval Augmented Generation) ;

\- génération de questions ;

\- correction IA ;

\- historique ;

\- suivi pédagogique futur.



\---



\## Utilisateurs cibles



\### Court terme

\- agents en formation ;

\- agents en maintien de compétences ;

\- auto-révision métier.



\### Long terme

\- formateurs ;

\- centres de formation ;

\- équipes métier ;

\- organisations réglementaires.



\---



\## Valeur apportée



Le projet vise à :

\- améliorer la rétention mémoire ;

\- réduire l’apprentissage passif ;

\- cibler les lacunes ;

\- accélérer les révisions ;

\- personnaliser les entraînements ;

\- créer une mémoire pédagogique intelligente.



\---



\## Différenciation



Le projet ne vise pas à créer un simple chatbot.



La cible est :

\- une plateforme cognitive pédagogique,

\- combinant IA,

\- RAG,

\- mémoire utilisateur,

\- adaptation pédagogique,

\- et suivi de progression.



\---



\## Vision long terme



Le système doit évoluer vers :

\- répétition espacée ;

\- mémoire des erreurs ;

\- adaptation dynamique des questions ;

\- profils cognitifs d’apprentissage ;

\- embeddings pédagogiques ;

\- moteur de révision adaptatif.



\---



\## Contraintes importantes



Le projet doit :

\- rester stable ;

\- conserver un fallback texte brut ;

\- éviter les régressions ;

\- rester modulaire ;

\- permettre des évolutions progressives ;

\- conserver une architecture compréhensible.



\---



\## Philosophie de développement



Le développement suit plusieurs principes :

\- petites étapes ;

\- validation continue ;

\- commits fréquents ;

\- architecture évolutive ;

\- dette technique limitée ;

\- explicabilité maximale.
